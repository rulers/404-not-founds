# Day 003 — Glass 404

## Concept

**SHATTER THE MISSING WORLD**。正面を覆うガラスを壊し、奥の無人の空間へ道を開く。404は遠方の扉にある標識で、破壊対象は画面全体。Liquidの俯瞰・連続操作と対照的に、奥行き・鋭い打撃・不可逆な欠損を扱う。

## Technology

Canvas 2D、TypeScript、CSS Modules。背景の床・扉・光はCSSで描き、ガラス面はオフスクリーンCanvasへキャッシュする。破片間の衝突を必要としないため物理エンジンや依存は追加しない。Canvasが使えなくてもCSSの世界とガラスの反射を残す。

## Implementation

- 画面比率に沿った三角形メッシュを作り、共有辺から隣接関係を構築する。数字の内外という判定は撤去。
- クリック／タップで打点周辺に距離依存の損傷を蓄積する。長押し約750msで強い衝撃になる。初撃の亀裂、同じ箇所への再打撃による欠損、別の箇所の破壊を区別する。
- ドラッグで傷を刻み、経路に近いセルを弱める。傷を先に作ると同じ強さの打撃でも破断が早くなる。ポインター移動ではReact stateを更新しない。
- 損傷したセルは隣接セルが支えを失うと連鎖破断する。残存材料38%未満で全面が崩れる。固定クリック数ではない。
- 穴は透明になり、ガラスの向こうが直接見える。破片には方向・重力・回転・減衰・反射を付ける。共通ナビは振動させない。
- 崩壊後約2.6秒は奥の世界を見せ、約1.2秒で面を再生する。
- 矢印キーで打点を移動し、Enter／Spaceで強く打つ。打点が穴になった場合は最も近い残存セルへ移る。キャンセル・フォーカス喪失は打撃にしない。
- reduced-motionでは振動・飛散を省き、欠損と再生を維持する。静止中・非表示時のRAFは停止。DPR上限2、RAF・イベント・ResizeObserver・Canvasキャッシュを解放する。
- 画面比率の変更時はガラスを再生成する。破壊状態はページ再訪・リサイズをまたいで保存しない。

## Lessons Learned

材質や変形量だけを変えても、巨大な数字を中央で触る構図は同じ体験に寄る。破壊対象を前景全体へ移すことで、404と操作対象の役割を分けた。亀裂の細密さより、傷と打点が次の欠損を変えることを重視する。

## Reuse

共有辺による隣接グラフと局所的な損傷の蓄積は、削る・切る・経路を弱める表現に応用できる。前版の亀裂生成・破片運動・キャンセル処理を再利用し、数字型の当たり判定は置換した。

## Validation / limitations

単体テストは全面メッシュ・隣接・打点・傷による破断の違い・連鎖崩壊・重力を対象とする。ブラウザではPC／モバイル相当の入力、余白の打撃、傷、再生、キーボード、reduced-motion、非Canvas、狭幅・横画面、Discover遷移を検証する。実施結果はPRに記録する。

光学的に正確な屈折や破片間衝突は計算しない。実機Safari／AndroidとLighthouse数値、触感に関するユーザー評価は未確認。
