# Day 006 — 404 Radio

## Concept

**存在しない周波数を探す。** 暗い展示空間の木製真空管ラジオを操作し、404 MHz付近で声の気配に同調する。約0.6秒待つと「お探しのページは……」が現れ、短い受信の後に **SIGNAL NOT FOUND** へ収束する。正しいアドレスに合わせても内容が届かないことが404体験。巨大な数字の変形や煙の再露出ではなく、装置・微調整・待つ時間を扱う。

承認済みのビジュアル方針を、木・織布・金属・ガラスを分けた独自SVGとCSSで制作。画像生成モックそのものは本番素材に使わず、写実的な写真と同一の質感を保証しない。真空管は天板の通気窓に小さく配置する。

## Technology

Next.js / TypeScript / CSS Modules / SVG / Web Audio API。新規依存・Three.js・バックエンド・マイク権限・外部音声サービスなし。Homeと個別URLは既存レジストリを共有し、darkテーマ。public素材にはassetPath()を使用する。

## Implementation

- 388〜420 MHz。左右ドラッグで0.025〜0.12 MHz/CSS pxの速度依存感度。離すと即停止し、保持のために指を置き続ける必要はない。周波数の自動吸着・慣性なし。
- スケールのタップで粗く移動。矢印キーは0.1 MHz、Page Up/Downは1 MHz、Home/Endは両端へ。role=slider、現在値、操作説明、フォーカス表示を持つ。
- ±2 MHzで接近。±0.4 MHz内で同調開始、±0.65 MHzを超えると解除するヒステリシス。約0.6秒後に受信、同調開始から約2.4秒後に消失。周波数を外して再度合わせると再探索。判定はlib/radio404.ts。
- 移動ごとにReact stateを更新せず、refとCSS変数・DOM属性で指針、ノブ、現在値を同期。Reactは段階・音声状態のみ更新。現在値の自動読み上げはOFF、状態字幕はpolite。
- 信号線は探索の断片線、接近の左右線、受信の波形、消失の平坦線。真空管の照明は安定。音声OFFでも全段階・結末が成立する。
- 音声は初期OFF。明示ボタンからAudioContextを生成・再開。低音量のノイズ、帯域フィルター、オリジナルの3音、同梱の短い英語合成音声「The page is」を使う。字幕は「お探しのページは……」。音声素材はFFmpegのflite/sltで独自の文を生成し、電話帯域とフェードを適用したWAV。実在放送・既存曲は使用しない。
- 音声の取得・デコード失敗時も雑音・音列・字幕を維持。AudioContextの開始失敗は無音で続けられる案内を表示。ミュートはコンテキストを閉じ、再ONで作り直す。高度な音量UI・音声バリエーション・隠し局はMVP外。
- 画面非表示で音声・同調待ちを停止。復帰時は待ちを再開し、非表示中に結末へ進めない。作品切り替え時は音源、コンテキスト、fetch、タイマー、入力イベントを解放。
- モバイルは水平の筐体を維持し、周波数と字幕を本体外に配置。ノブの操作領域は72px以上。短い横画面は本体と表示を左右に分ける。共通ナビは変更しない。
- 常時RAF、点滅、全面ノイズアニメーションなし。reduced-motionでも直接操作・段階変化を維持。JavaScriptなしでは静止画・説明・共通ナビが残る。

## Lessons Learned

狭い数値の完全一致を要求するより、低速入力の精度・広い許容幅・解除幅の差・指を離して待てることが同調体験を支える。生成モックの見栄えと実際に操作可能な素材は別であり、実ブラウザのスクリーンショットと実入力で検証する。

## Reuse

速度依存ドラッグ、段階付きの保持判定、ヒステリシス、ユーザー操作からの音声開始と終了処理は、調整機器や探索作品へ応用できる。共通の機器基盤への抽象化はしない。

## Validation / limitations

単体試験：速度と精度、周波数境界、保持・受信・消失・再探索、手ぶれと解除幅。
ブラウザ試験：PC/モバイル相当の実ポインター入力、キーボード、無音の結末、音声ON/OFF・開始失敗、Discover、390px/320px/横向き、reduced-motion。実施結果はPRに記載。

実機Safari/Android、実際の聴感・触感、人間による最終ビジュアル評価は未確認。Chromium上の音声開始成功を、実機の音質評価とは扱わない。同期字幕は音声を逐語書き起こしたものではなく、受信段階の日本語表現。合成音声の読み上げ自体は英語。
