# Day 007 — 404 Vending Machine

## Concept

**NOTHING MART — Everything you’re missing.** 正常に動く自販機で、手に入るはずの商品だけが見つからない。朱赤・ミント・クリーム、温かい庫内灯、縦長の機械が主役。Radioの暗い空間・微調整とは、構図・入力・動き・結末を変えた。

2026-10-20分の作品として登録。実装・検証日は2026-10-21 JST。登録日による予約公開はなく、PRマージ前は未公開。最新main `90bdf69` の登録が006までだったため007を使用し、Paper Planeの未マージ変更には依存しない。

ユーザーによる設計レビュー完了後に制作。初期画面に前景商品や結果を表示しない。モックは外観目標であり、生成画像を本番素材へ流用せず、自作SVG・CSSで構成した。

## Technology

Next.js / React / TypeScript strict / CSS Modules / 自作SVG。新規パッケージ、Three.js、物理エンジン、外部素材・フォント、音声、決済、常時RAFは使用しない。既存レジストリ・lightテーマ・Galleryを使い、Homeと固定URL `/404/007/` は同一コンポーネント。サムネイルは実ブラウザの初期表示を900×600 PNGへ保存。

## Implementation

### 機構と連続性

- まずA1とB2で選択→排出→取り出し→結末→再購入を実ブラウザで確認し、その後A2とB1を追加。
- ボタンが沈み、コイルが回転。約1秒の引っかかりの後、選択商品の棚位置に応じた起点から約0.7秒で落下し、排出口で弾む。
- 到着後はユーザーを待つ。フラップを押す一操作でフラップが開き、中の同じ商品が約0.65秒で手前へ移動・拡大する。
- 商品は独立した結果パネルへ置換しない。取り出し前後のSVGを維持し、PCでは本体の手前右側、スマホでは排出口の手前で扱う。
- 4商品はA1の空箱、A2の切れる鎖、B1の透明な写真、B2の消える缶。A2はつながった中央輪を隙間のある輪へ置換し、短い衝撃線の後に左右の鎖が遅れて落ちる。文言の差だけで結果を変えない。
- 通常商品はユーザーが開封するまで待つ。B2だけは取り出し後に缶そのものが消える。結果は時間で閉じず、レシートの「もう一つ選ぶ」で再購入へ進む。

### 状態と後始末

`lib/vending-machine404.ts` の純粋な遷移関数で `idle → coil → drop → ready → collect → inspect/reveal → result` を管理。無効な操作を拒否し、追加購入をキューにしない。アニメーション終了イベントに依存せず、各段階のタイマーをeffectで生成・解除する。

非表示時はタイマーの残時間を保持し、CSSアニメーションを一時停止。復帰時は残りから再開する。作品切り替え・Escapeによる中断で、タイマーとvisibilityイベントを解放。フォーカス復帰に新たなRAFやタイマーを使わない。Reactの更新は段階遷移時だけで、ポインター移動は購読しない。

### 操作・配色・アクセシビリティ

- マウス・タップで商品ボタン→フラップ→開封→再購入。ドラッグ必須操作なし。
- Tabで移動、Enter/Spaceで実行。取り出し可能時はフラップ、開封可能時は開封ボタン、結果時は再購入ボタンへフォーカス。再購入時は選択した商品ボタンへ戻る。取り出し以降はEscapeで中断・復帰できる。
- ボタンの操作範囲は44px以上。購入中はaria-disabledと遷移関数で再購入を拒否する。状態は日本語のpoliteな通知、図形は装飾として扱う。
- 作品専用CSSに朱赤・ミント・クリーム・濃茶を限定。共通ナビゲーションはlightテーマのCSS変数を維持する。
- reduced-motionでは移動・揺れ・回転を省略し、短い状態切り替えで全操作と異なる結末を残す。
- JavaScriptなしでは静止筐体と操作不可の説明、通常のナビゲーションが残る。
- 縦画面では結果を下部前景に置き、状態説明を上部へ配置。短い横画面は作品内をスクロールし、操作範囲を縮めすぎない。フォーカス移動先を共通ヘッダー・下部情報の余白内へスクロールして、キーボードでも次の操作が見えるようにする。

## Lessons Learned

排出と結果を別パネルにすると物を扱うつながりが切れる。同じSVGの位置・大きさ・状態を変えて、到着から開封までをつなぐことを優先した。スマホでは大きな商品よりもフラップ・開封・再購入の位置を優先する。

A1/B2の経路を先に通すことで、開封を待つ商品と取り出した時点で結末になる商品の両方を確認できた。鎖の切断は左右移動だけにせず、接続部分の変化と遅れて落ちる動きを分ける。

## Reuse

無効操作を拒否する段階管理、非表示時に残時間を保持するタイマー、操作段階に応じたフォーカス移動は、開封体験・製品デモ・短いミニゲームに応用できる。汎用の機器基盤への抽象化はしない。

## Validation / limitations

ローカルでformat / lint / 単体30件 / typecheck / basePath付きStatic Export成功。Chromium PC・モバイル相当E2Eは全体75件成功・7件スキップ（既存のPC対象外センサー試験）。最終のフォーカス・開封演出調整後も作品別8件成功。PRのCI結果はPR本文へ記録する。初期状態、4商品の全経路、連打、フォーカス、Escape、非表示復帰、狭幅・横画面、JavaScriptなし、Discover・直接URLを対象とする。

実機Safari/Android、実機の触感、Lighthouse測定、最終的な作品体験のユーザー評価は未確認。生成モックの質感とピクセル単位の一致は要件にせず、動作するSVG・CSSの立体感を目標とする。鎖などは演出であり物理シミュレーションではない。自動テストの成功を「笑える作品として成功」と同一視しない。
