# Day 008 — 404 Paper Plane

## Concept

**A letter to nowhere.** 自分で飛ばした紙飛行機が、存在しない宛先を探して滑空し、同じ出発地点へ帰ってくる。帰還した同じ紙に「404 — DESTINATION NOT FOUND / RETURNED TO SENDER」の赤い返送印が押される。

2026-10-21分の作品として登録。制作・検証日は2026-10-22 JST。最新main `1d16285` に登録済みなのが007までであることを確認して008を採番。専用の `feature/404-008-paper-plane` をmainから作成し、developの同期や他作品の未マージ変更は含めない。

淡い青から生成りへの空、柔らかな雲、セリフ体の詩、折り目と陰影のある白い紙が主役。初期画面には返送印も巨大な404も表示しない。静的なメインビジュアルから、操作・滑空・帰還・次の投函までを一つの紙でつなぐ。

## Technology

Next.js App Router / React / TypeScript strict / CSS Modules / 自作SVG / CSS Transform。飛行中だけrequestAnimationFrameを利用し、待機中には描画ループを回さない。新規依存・Three.js・物理演算・外部画像・外部フォント・音声・バックエンドなし。

最新mainのNode.js要件に合わせ、検証にはNode.js 24.22.1を使用。既存のlightテーマ・Gallery・レジストリ・Homeとのコンポーネント再利用・Static Export・basePathを維持する。

## Implementation

### 入力

- 操作は紙飛行機のbutton内だけで開始し、Pointer Captureで領域外へのドラッグも追跡する。touch-action:noneはこの操作領域だけに適用。
- 機体は出発点に留め、ドラッグ方向に機首を向ける。方向ガイドと強さの数値を表示し、リリースで発射。14px未満の入力は発射しない。距離から強さを求め、12〜100%に制限。
- 左右キーで10度ずつ方向変更、上下で強さを調整、Enter/Spaceで発射、Escapeで狙いをキャンセル。支援技術からの仮想クリックでも発射できる。通常の短いタップは誤発射させず、引いて離す案内を表示する。
- 飛行中は追加発射を無視する。返送印は狙い直しやキャンセルでは消さず、次の発射時に消す。

### 経路と入力値の対応

`lib/paper-plane404.ts` の純粋関数で3本の3次Bezier曲線を生成する。

1. 入力方向へ出発する滑空。
2. 横方向へ広がる大きな旋回。
3. 出発点へ減速して戻る帰路。

入力方向を基準軸、直交方向を旋回軸とする。画面内に広く収まる側を選んで経路を構成し、制御点の凸包が安全領域に収まる最大倍率を計算する。その後に強さによる倍率を掛けるため、狭いスマホでも弱い投げ方と強い投げ方が同じ大きさへ飽和しない。

曲線の接続点では接線方向をそろえ、各フレームの機首角度は曲線の微分から求める。少し縮小して遠近感を出し、帰還時は同じ位置・同じDOMの紙を拡大する。全経路は閉じ、終点は厳密に原点。ランダムな風は加えず、入力と結果の対応を優先した。

初期の飛行時間は強さに応じて約6.4〜7.6秒。帰路では進行を緩めて着地させ、紙を拡大してからインクを表示する。返送印はSVG内の図形・文字であり、独立した結果カードを作らない。結果は時間で消えず、紙をそのまま再操作できる。再発射は拡大中の紙と同じ大きさから始め、約0.65秒かけて飛行中の大きさへ滑らかに縮小する。

### ライフサイクル・アクセシビリティ

- ポインター移動・毎フレームの位置更新はref・CSS変数へ直接反映。Reactは操作段階・返送状態・読み上げメッセージが変わる時だけ更新する。
- pointercancel / lostpointercapture / 操作対象のblurで狙いを中断。リサイズ中の入力・飛行は手元へ戻す。帰還済みの返送印は維持する。
- 非表示・window blurでRAFを停止。復帰時の最初のフレームは時刻だけを再設定し、非表示の経過時間を飛行へまとめて加えない。通常フレームも積算を50msに制限する。
- アンマウント時はRAF、Pointer Capture、ResizeObserver、pointer・keyboard・visibility・focus・media queryイベントを解除する。
- キーボードフォーカスは機体の輪郭線で表し、拡大時に巨大な枠が共通UIを覆わないようnon-scaling-strokeを使う。
- 操作状態は日本語で読み上げ、角度・強さはbuttonのラベルとoutputへ反映。SVGは装飾として扱う。
- reduced-motionでは遠方への移動・旋回を省略し、約0.9秒の短い送信・帰還の状態変化と同じ紙への返送印を残す。飛行中に設定が変わっても静かな帰還へ切り替える。
- JavaScriptなしでは空・紙・詩と操作不可の説明、共通ナビゲーションが残る。

## Lessons Learned

経路を画面に収める計算を投げる強さの適用後に行うと、モバイルでは大半の入力が同じ最大半径に縮められる。先に最大経路を決めてから強さを掛けると、入力差を維持できる。

SVG内の返送印へCSSのtransformを上書きすると、紙の座標から浮いて見える。返送印の位置・向きはSVG座標で決め、インクの演出は透明度だけで行う。待機から帰還まで同じbutton/SVGを保持し、「自分が送った紙」を見失わないことを優先する。

## Reuse

入力方向を基準とする曲線生成、制御点からの境界制限、接線に沿う姿勢、可視状態に連動するRAFは、送信デモ・小さな飛行体・循環する移動演出に応用できる。共通のゲームエンジンや作品管理基盤には抽象化しない。

## Validation / limitations

ローカルではformat:check / lint / 単体33件 / typecheck / basePath付きStatic Exportが成功。既存作品を含むE2Eは91件成功・7件スキップ（既存のPC対象外センサー試験）。再発射のスケール連続性の調整後も作品別のPC・モバイル相当10件がすべて成功。初回の全体試験と最終調整後のCI結果を区別し、最新CIの結果はPR本文へ記録する。

単体試験は入力の閾値・上限、24方向×3段階の強さ×PC/狭幅/横画面での安全領域、機首と接線、厳密な帰還、モバイルでも残る強弱差を検証する。

ブラウザ試験は実マウス・CDPタッチの3通りの発射、同じDOMでの帰還と再発射、短いタップ、ポインター中断、blur、リサイズ、キーボード、reduced-motion、非表示復帰、ナビゲーション、直接URL、Discover、JavaScriptなしを対象とする。最新の実施結果はPR本文に記録する。

実機Safari/Android、実際の触感、ユーザーの最終的な体験評価、Lighthouse測定は未確認。大幅に低いフレームレートでは安全な時間積算により飛行が長くなる場合がある。スマホの返送時は読みやすさのため紙を拡大し、翼端が画面端で一部切れる場合がある。
